## `801C81EC -> 80015590` boundary

The bootstrap line is already represented as direct semantics:

- `PrStageStatusBankDirectClearProducer(...)` emits `Call80015590` when
  `!800916DA` and `800916F0 != 1`.
- `801C81EC` converts that trace into `ActionKind801C81EC::Bootstrap15590`.
- `BuildBootstrap15590DirectPlan801C81EC(...)` validates the action kind,
  `psxFunction == 80015590`, scene id, zcompo loader identity, and loader
  offset `0x12C`.
- The loader runner owns the direct skeleton for `80015590 -> 8001AC18`; the
  thick part is the host block start/tick/feedback bridge.

Thin-shell candidates:

- `TickBootstrap15590Block(...)`: still decides pump/callback/CD branch and
  applies feedback in the host adapter.
- Per-frame block tick/drain in `pr_scenes.cpp`: still acts as a broad
  transaction shell around lifecycle blocks.
- Host block start/path resolution: may be thinned, but direct row identity to
  Win filesystem path resolution remains a platform adapter responsibility.

Do not delete:

- `ActionKind801C81EC::Bootstrap15590`, `psxOrder`, `psxFunction`, scene arg,
  row identity, and loader offset fields.
- `BuildBootstrap15590DirectPlan801C81EC(...)` validity checks.
- Blocking/feedback semantics; only move their carrier if the same observable
  request and completion facts remain.

## `801C81EC -> 80019148(&80092F10)` boundary

The save-ui line must start from the existing `80092F10` direct prefix:

- `80019148(a1)` passes the caller pointer through to `80018FB0`; for Stage1
  the caller pointer is `&byte_80092F10`.
- `800185D0` writes the suffix at `a3 + 1`, so for Stage1 the write target is
  `80092F10 + 1`, not a fresh host buffer.
- Current C++ already starts save-ui with
  `GetSaveStatusPrefix80092F10()` and `Start19148(ctx, &seed80092F10)`.
- `80019458` state15 consumes the known direct memory source and copies to the
  actual card-read payload view; it must not use host payload bytes as success
  authority.

Forbidden authority sources:

- `PrCard::Payload()`, Win save files, empty/zero-filled buffers, replay sampled
  payload bytes, or host I/O success.
- case17/card-read payload bytes as proof of PSX success. Payload is only a row
  source after the lower read facts are complete and the PSX success gate is
  satisfied.

Remaining optional evidence window:

- A narrow `80019148/800185D0/80019458` callsite export may still be useful if
  we change the save-ui host bridge. It should only verify pointer pass-through,
  `a3+1` suffix write, and state15 copy/commit. It should not expand into
  lower-CD, RGB, Rail/GTE, or MenuHelp.
