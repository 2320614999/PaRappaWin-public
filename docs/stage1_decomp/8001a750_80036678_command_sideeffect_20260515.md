# 8001A750 bit-clear command side-effect

Evidence:

- IDA export:
  `docs/stage1_decomp/ida_export_8001a750_80036678_command_sideeffect_20260515.json`.
- `8001A750` calls `800364D0(1,status)`.
- If the return is not `2`, `8001A750` returns `0`.
- If the return is `2` and `status[0] & 0x20` is set, `8001A750` returns `1`.
- If the return is `2` and the bit is clear, `8001A750` calls
  `80036678(1,0)` and then returns `0`.

For the exact `80036678(1,0)` call:

- `a1 == 1` skips the restart-command branch.
- `a2 == 0` skips the pre-Setloc branch.
- The final command is `800375BC(1,0,0,1)`.
- `800375BC(1,0,0,1)` has no args, clears `byte_800573D4`, writes
  `byte_80057119 = 1`, writes CD command `1`, and skips the wait loop.

Direct-port boundary:

- This only closes the `8001A750` bit-clear side effect.
- It does not authorize generic `80036678` success, lower-CD success, STR/XA
  progress, file/ISO readability, payload facts, or renderer state.
- `8001A750` return mapping still comes only from `800364D0(1,status)` and the
  PSX branch above.
