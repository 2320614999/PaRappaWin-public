# Movie1 outro helpers `80020308` / `80020248` 2026-05-19

Scope: Stage1 Movie1 / clear-tail outro frame helper verification.

## IDA facts

- `80020308(a1)`
  - If `gp+0xC4 == 0`, calls `800271E4(0)`.
  - If `a1 != 0`:
    - at `gp+0xC4 == 15`, calls `800271E4(1)`;
    - while `gp+0xC4 < 15`, draws `8001F230(5)`;
    - from `gp+0xC4 >= 15`, draws `8001FEB4(0)` and returns `1`;
    - increments `gp+0xC4`, completes when the incremented value reaches `31`.
  - If `a1 == 0`:
    - draws `8001FEB4(0)`;
    - increments `gp+0xC4`, completes when the incremented value reaches `16`;
    - returns `0`.
  - On completion, writes `gp+0xC4 = 192`.

- `80020248(a1)`
  - If `gp+0xC4 == 0`, calls `800271E4(1)`.
  - If `a1 != 0`:
    - at `gp+0xC4 == 15`, calls `800271E4(0)`;
    - while `gp+0xC4 < 15`, draws `8001F230(5)`;
    - from `gp+0xC4 >= 15`, draws `8001C864(5)`;
    - increments `gp+0xC4`, completes when the incremented value reaches `31`.
  - If `a1 == 0`:
    - draws `8001CE30(5)`;
    - increments `gp+0xC4`, completes when the incremented value reaches `16`.
  - Always returns `192`; on completion, writes `gp+0xC4 = 192`.

## Current direct implication

- `ResolveOutroSub80020308Step(...)` and `ResolveOutroSub80020248Step(...)`
  already match the helper selection, cue points, return value, and completion
  thresholds above.
- The remaining visible frame/corner risk is not this state machine; it is the
  consumer path for the emitted `8001C864` frame submits.
- Common-lyrics `8001C864` frame submit order starts at PSX call order `0`, so
  the renderer consumer must encode it as non-zero renderer order before
  submitting sprites, matching the Movie1 raw/template draw plan.
