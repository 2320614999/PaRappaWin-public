## Baseline

`80043A14` is the text append/format producer. It selects a record slot, appends
text into `record+0x24`, advances `record+0x28`, enforces `record+0x1C`, and
null-terminates. It supports literal bytes plus `%d/%x/%X/%c/%s`-style varargs
from the MIPS argument save area.

`800436F0` is the consumer/flush. The only xrefs in this branch are:

```text
80026478 -> 800436F0(-1)
80026DD4 -> 800436F0(-1)
```

Therefore `80026478` and `80026DD4` are flush callsites, not independent text
producers. The producer work happens earlier in `80026314` and in the
`80026B94(event_id==2 && word_800916F6 != 0)` frame-tail branch.

## 80026314 menu/help producer

Function shape:

```text
sub_80026314(a1)
  v2 = *(int**)a1              ; menu/help row bank
  group_count = *(a1 + 8)
  selected_group = *(a1 + 4)
  append "\n\n\n\n"
  for group_index in 0..group_count-1:
    append group marker
    append "%s:" with group title
    for item_index in 0..item_count-1:
      build stack string = item marker + item label + pad spaces to len 6
      append stack string
    append "\n"
  append "\n\n~c222      O: OK   X: CANCEL~c888\n"
  flush 800436F0(-1)
```

Call order:

| Order | PC | Producer/consumer | Effective arguments | Notes |
|---:|---|---|---|---|
| 1 | `80026348` | `80043A14` producer | `a0 = "\n\n\n\n"` | Literal append. No vararg dependency. |
| 2 | `80026380` | `80043A14` producer | `a0 = "~c000    "` or `"~c888 >>>"` | Literal append. Selection depends on `*(a1+4) == group_index`. |
| 3 | `80026394` | `80043A14` producer | `a0 = "%s:"`, `a1 = *(group+0x04)` | Vararg `%s`; requires preserving the second argument/pointer. |
| 4 | `80026424` | `80043A14` producer | `a0 = stack buffer` | Stack buffer already built by `strcpy/strcat`; final append is literal from the prepared buffer. |
| 5 | `80026448` | `80043A14` producer | `a0 = "\n"` | Literal append after one group. |
| 6 | `80026470` | `80043A14` producer | `a0 = "\n\n~c222      O: OK   X: CANCEL~c888\n"` | Literal footer append. |
| 7 | `80026478` | `800436F0` consumer | `a0 = -1` | Flushes selected/current record. Not a producer. |

String construction details:

- Group marker is direct-literal: `~c000    ` for normal group, `~c888 >>>`
  for the selected group.
- Group title append is not direct-literal: format string `%s:` consumes the
  group title pointer from `a1`.
- Item marker is first built outside `80043A14`: `~c000 ` for normal item,
  `~c888*` for the selected item.
- Item label comes from `*(item+0x08)` and is concatenated into a stack buffer.
- Item label is padded with spaces until the label length reaches 6. The
  producer call at `80026424` sees only the completed stack string.
- Footer literal includes PSX color tags and the OK/CANCEL help text.

|---|---|---|

| `80026424` | Yes, after preserving stack-buffer construction | `80043A14` receives a completed C string; the `strcpy/strcat/strlen` gap belongs to `80026314`, not to `80043A14`. |

Required unknown/gap handling:

- Preserve `80026314`'s local stack-buffer producer until the full function is
  direct-ported. Do not replace it with an approximate menu renderer.
- Preserve the `%s:` vararg boundary at `80026394`, or explicitly preformat the
  exact string before calling the current non-vararg Win wrapper.
- Preserve the menu record layout source `*(a1)`, `*(a1+4)`, `*(a1+8)`, row
  stride `0x24`, item label pointer at item `+0x08`, and selected item index at
  group `+0x20`; these are caller-owned data-flow facts, not `80043A14` facts.

Call order for the StageClear branch:

| Order | PC | Producer/consumer | Effective arguments | Notes |
|---:|---|---|---|---|
| 1 | `80026D8C` | `80043A14` producer | `a0 = "\n\n\n~c000StageClear: "` | Direct literal append. Guarded by `event_id==2 && word_800916F6 != 0`. |
| 2..7 | `80026DAC` | `80043A14` producer | `a0 = &8006EC14`, `a1 = byte_80092F1D[i]`, `i = 0..5` | Vararg/data-table call. Must not be collapsed to a hardcoded string. |
| 8 | `80026DD4` | `800436F0` consumer | `a0 = -1` | Per-frame flush after draw/wait/end-frame. Not a producer. |

`8006EC14` static bytes begin with:

```text
25 64 00 00 ... "SCENE9" ... "SCENE8" ... "SCENE7" ... "SCENE6" ...
"SCENE3" ... "SCENE2" ... "SCENE1" ... "SCENE0" ... "XTIME" ...
"LOWER2" ... "LOWER1" ... "NORMAL" ... "HIGH" ...
```

The first bytes decode as `"%d\0"`, followed by table-like data. Because the
call passes `byte_80092F1D[i]` in `a1`, `80043A14` will consume at least one
vararg for the leading `%d`. The table's remaining strings may be adjacent data
rather than one single printable format. Static evidence is not enough to
replace this with a constant text block.

Direct hookup classification:

| PC | Can call `PsxCall80043A14_TextAppend` directly? | Reason |
|---|---|---|
| `80026D8C` | Yes | Plain literal; no vararg dependency. |
| `80026DAC` | No | `&8006EC14` is a format/data pointer and `a1` comes from `byte_80092F1D[i]`; current wrapper has no PSX vararg formatter. |
| `80026DD4` | No | This is `800436F0(-1)` flush, not append. |

Required unknown/gap handling:

- Keep the six `80026DAC` calls as vararg/format calls until either
  `80043A14` gains PSX-compatible vararg input or this exact `8006EC14` format
  table is decoded with runtime-backed argument values.
- Keep `byte_80092F1D[0..5]` as runtime data. The static export shows the xref
  and sample bytes, not the live values for the StageClear frame.
- Keep `80026DD4` on the text flush path. It should consume the same record bank
  as the preceding append calls and clear `record+0x28` / first text byte via
  `800436F0`.

## Implementation boundary implied by this static pass

Safe direct-append callsites for the current non-vararg Win wrapper:

```text
80026348  append "\n\n\n\n"

80026424  append caller-built stack string

80026470  append footer literal

```

Callsites that must remain vararg/unknown-gap aware:

```text

80026DAC  append &8006EC14 with byte_80092F1D[i] in a1
```

Flush-only callsites:

```text

80026DD4  800436F0(-1), dispatcher frame-tail flush
```

Do not route flush callsites through `PsxCall80043A14_TextAppend`. The correct
split is append first, then `PsxCall800436F0_TextFlush(state, -1)`.
